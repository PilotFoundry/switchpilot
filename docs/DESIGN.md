# DESIGN：个人自用菜单栏面板 v0.1

日期：2026-10-18；对应 PRD：`docs/PRD.md`；实现约束：`docs/TECH.md`。

## 1. 设计原则

- **原生优先**：AppKit 状态项 + SwiftUI 面板 + SF Symbols，不做自定义皮肤、不做 Liquid Glass 视觉稿。
- **状态可见、不假装成功**：每个功能都有明确状态（未授权/进行中/已开启/失败）与真实错误信息。
- **最小权限**：启动不弹权限框；只有用户显式操作才请求 Automation / 打开辅助功能设置。
- **破坏性动作二次确认**：屏保、锁屏会立即改变屏幕状态，必须确认并说明可能的密码解锁影响。
- **默认安全**：不写全局偏好、不改 TCC、不控制原版 One Switch、不在后台自动触发。

## 2. 信息架构

```
菜单栏图标（NSStatusItem, variableLength, SF Symbol switch.2）
└── 点击 → NSPopover（behavior: transient, 宽 320）
    └── PanelView（SwiftUI）
        ├── Header：产品名、版本、"个人自用"标识
        ├── Keep Awake 区：Switch、时长 Picker、剩余时间/状态
        ├── Dark Mode 区：Switch、当前系统外观、权限/错误状态、授权入口
        ├── Quick Actions 区：启动屏保、锁定屏幕（带说明与确认）
        └── Footer：原应用未修改说明、退出按钮
```

v0.1 只有单面板；不提供设置窗口、偏好页、快捷键与登录项。

## 3. 状态模型

每个功能的状态是有限枚举，UI 只展示真实状态：

| 状态 | 含义 | 呈现 |
|---|---|---|
| `inactive` | 关闭且可操作 | 灰色/普通控件 |
| `active` | 已开启且有读回证据（保活断言 / 深色模式读回） | 绿色状态点 + 文案 |
| `pending` | 操作进行中 | 控件禁用 + 简短进行中文案 |
| `needsPermission` | 缺少 Automation 或 Accessibility | 黄色提示 + 授权按钮/设置入口 |
| `denied` | 用户或系统拒绝 | 红色提示 + 错误码 + 设置入口 |
| `unavailable` | 系统能力不存在（如屏保引擎缺失） | 灰色说明 + 禁用动作 |
| `failed` | 操作返回错误 | 红色错误文案（含 OSStatus/描述） |

规则：只有实际读回成功才进入 `active`；读取失败或无法读回时显示"已请求，未确认"而不是"成功"。

## 4. 交互明细

### 4.1 显示器保活

- `Toggle("保持亮屏")` + Picker：15 分钟 / 30 分钟 / 60 分钟 / 无限期（默认无限期）。
- 开启：创建公开 IOKit 断言（PreventUserIdleDisplaySleep），按 ID 读回 type/level 后进入 `active`。
- 计时：面板每秒刷新"剩余 14:59"；到时自动释放并回到 `inactive`。
- 修改时长：仅在开启时重启会话（先释放再创建）；关闭、退出、错误路径都释放。
- 文案边界："仅阻止空闲休眠；不阻止合盖或手动睡眠"。

### 4.2 系统深色模式

- Toggle 显示系统当前外观（深色/浅色；无权限时也可从全局偏好只读判断）。
- 点击切换：
  - `allowed`：执行 AppleScript set → 读回 → `active/inactive`。
  - `needsPermission`：不发送写操作；显示"需要你的授权"与两个入口：
    - "请求授权…"（明确的用户动作，触发系统 Automation 提示）；
    - "打开系统设置 › 隐私与安全性 › 自动化"。
  - `denied`：显示错误码与设置入口，不重试。
- 失败不改变界面上的外观状态；读回失败显示"已请求，未确认"。

### 4.3 启动屏保

- 动作按钮 `启动屏保`（非持续开关）。
- 点击后 NSAlert 确认：说明会立即启动系统屏幕保护，如启用唤醒密码可能需要解锁。
- 确认后调用系统 ScreenSaverEngine；成功显示"已请求启动"，失败显示具体错误；无法读回屏保状态时明确写"未确认"。

### 4.4 锁定屏幕

- 动作按钮 `锁定屏幕`（非持续开关）。
- 点击后先检查权限：Automation（System Events）与 Accessibility。
  - 任一缺失：显示缺少哪一项、错误码/布尔值，提供"请求自动授权…"与"打开辅助功能设置"；**不发送按键**。
  - 权限齐备：NSAlert 确认（锁屏后需密码解锁）→ 发送与原版等价的 Ctrl+Cmd+Q 按键 → 1 秒后 best-effort 读取锁屏状态；读不到则显示"已请求，未确认"。
- 不提供私有 API、不改 TCC、不重试。

### 4.5 退出

- Footer 的"退出"调用 `NSApplication.terminate`；退出前释放保活断言、停止计时器。

## 5. 视觉规范

- 系统字体（-apple-system/PingFang SC），正文 13px，标题 14px semibold，状态说明 12px。
- 间距 8/12/14；面板内边距 14；分隔线用系统 Divider。
- 图标优先 SF Symbols：`switch.2`（应用）、`moon.fill`（深色）、`display`（保活）、`lock.fill`（锁屏）、`play.rectangle`（屏保）。
- 颜色只使用系统语义色（`Color.green/orange/red/secondary`），不做品牌色；支持浅色/深色外观。
- 无动画或最小动画；尊重"减少动态效果"（v0.1 无自定义动画）。
- 弹窗尺寸自适应内容，不强制固定宽度；面板固定宽 320，高度随内容。

## 6. 无障碍与键盘

- 使用 SwiftUI `Toggle`/`Button`/`Picker`，默认支持 Tab 聚焦与 Space/Return 激活。
- 每个控件带中文可读标签与必要帮助文案；状态变化用 `accessibilityValue`/文案体现，不只靠颜色。
- 不使用仅图标无标签的可点击元素（菜单栏图标除外，提供 accessibilityDescription）。
- v0.1 不做 VoiceOver 全路径验收，列为 TESTPLAN 手动项。

## 7. macOS 27 适配

- 使用当前 SDK（27.0）构建；面板跟随系统外观与材质，不自定义 Liquid Glass。
- 菜单栏通过 `NSStatusItem`（而非 NSStatusBarButton 私有行为）；面板用 `NSPopover` + SwiftUI，属于稳定公开路径。
- 不使用已弃用 API；深色模式、锁屏脚本目标为 System Events 的公开脚本字典项。
- 不声明分发级 Sandbox/公证；个人使用 ad-hoc 签名，说明在 README/TECH。

## 8. 错误与日志

- UI：错误显示在对应功能行内，包含人类可读原因与 OSStatus（如有）；设置入口仅在相关权限错误时出现。
- 日志：使用 `os.Logger`（subsystem `local.personal.SwitchPilot`）记录启动、权限状态、动作结果与错误；不记录用户隐私内容、不落盘明文敏感数据。
- 不吞错：脚本/进程/IOKit 错误必须向上传递到 UI。
