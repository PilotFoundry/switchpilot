04 / 新面板（离屏渲染，实际 SwiftUI）

这次改了什么

  • 状态胶囊「保活关闭 / 保护中」；主开关 + 时长 + 进度。
  • 权限按缺失项生成唯一 CTA：缺 Automation → 申请；缺辅助功能 → 去授权。
  • 首启引导含"申请全部权限 / 重新检查 / 稍后再说"，并明确拒绝后保活/屏保可用。
  • 引导展开时隐藏重复权限 callout，面板逻辑高度 710pt；无引导 672pt。
  • 底部：权限摘要、使用说明、设置…、退出；右键菜单同名入口。

渲染由应用 `--dump-panel` 离屏生成（2x），不代表真机 popover 的材质/定位；真机验收见 M1/M5/M8。

05 / 权限流程与撤回研究

  1. 启动时不请求任何 TCC；面板显示当前状态。
  2. 首次打开引导：点「申请全部权限」→ Automation 系统弹窗（允许/拒绝）→ 若辅助功能未授权，调用系统提示并打开设置让用户勾选 → 回面板「重新检查」。任一步拒绝：保活/启动屏保仍可用，深色/锁屏显示缺失项与设置入口。
  3. 设置页保留「申请全部权限」「重新检查」「去授权辅助功能」与两个系统设置深链；应用重新激活时自动刷新。
  4. 再次申请：已拒绝的 Automation 通常不再弹系统窗，只给系统设置入口；未决定/目标未运行时仍可请求。

批量撤回结论：`tccutil reset Accessibility|AppleEvents <bundle>` 在本机可用（默认仅当前用户；sudo 才影响所有账户），但 Apple 定位为开发/测试工具、无恢复 API、`reset All` 会清空所有应用决定。因此应用内**不自动执行**；设置页提供系统设置深链，README 给出手动 bundle-scoped 命令，不做 sudo/All/静默执行。

06 / 登录启动与品牌

登录时启动（SMAppService）

  • 设置 › 登录开关；状态：未开启/已开启/需要批准/未找到；失败显示真实错误。
  • 本机实测：初始 `notFound` → `register()` 后 `enabled` → `unregister()` 后 `notRegistered`（`evidence/raw/app/login-item-test.log`）。
  • 登录后是否真正启动、重建后是否失效、requiresApproval UI 需现场 M8。

图标

  • 应用图标：1024 画布、824 内容居中、squircle；深绿渐变 + 奶油 S；16–1024 icns。
  • 菜单栏：自绘 S monogram template 图标；替换 SF Symbol switch.2。
  • 右键菜单：设置… / 使用说明 / 退出；左键面板。
