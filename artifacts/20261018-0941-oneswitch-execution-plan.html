01 / 本轮要得到什么

本轮目标是用 REA + Ghidra 验证三个代表性功能能否被解释并独立实现，得到继续 / 缩范围 / 暂停的可追溯结论。用户已授权执行；第 1 步已验证，证据见 evidence/baseline.md，后续按里程碑推进。

默认个人研究、Apple Silicon / macOS 27、单人顺序推进；先不购买软件、不引入云端分析服务。默认样本为常规保活、系统深色模式、Night Shift；这是技术覆盖选择，不代表用户已确定首版功能。

六步预计约 10.5–22 个有效工时，即约 2–4 个工作日（按每日 6 小时），不含许可、下载和等待用户可测试时段。15–40 万累计输入+输出 token 沿用前次规划估算，不是已测结果或硬保证；第三步后以实际 usage 重估，不作为无限重试额度。

2026-10-18 复核：系统仍是 27.0.1（26A434），One Switch 仍是 1.35.4（440），主程序 hash 与前次相同；ZIP 仍不存在。PATH 未发现 REA/Ghidra，Applications 未发现 Hopper/Ghidra，非全盘审计。已有 Xcode.app；Java/JDK 和 Xcode 首次配置在执行时确认。

03 / 风险与决策规则

遇到的情况处理方式是否继续
REA 桥接失败，但 Ghidra 可用直接用 Ghidra 导出证据；把桥接问题单列继续静态分析
关键函数仍无法解释对同一函数用 Hopper 作有界复核，先核查试用范围仅在它能回答具体疑问时增加工具
Night Shift 没有可接受接口记录不支持或系统设置入口，不把旧私有实现自动移植缩范围；其余功能继续
缺少 Xcode 许可、权限或测试硬件完成独立的静态工作，列出动态验证缺口不声称运行验证通过
核心能力可实现，恢复测试通过输出候选范围和实测预算可进入下一轮产品规格
用户必须能力没有可接受路径写清原因、证据和重新启动条件暂停该产品方案

保护边界：原应用、签名、许可证和数据保持原样；不上传整个包、不关闭 SIP、不改 TCC 数据库、不重签原应用。真实许可、凭据、付费或全局修改到执行时处理，不为普通局部读取和导出设置逐项审批。

项目局部安装优先，记录配置差异与回退。结束时只移除本轮创建且确认不再需要的工具/配置，保留证据。默认同一执行者顺序推进；仅在一个具体问题需要复核时增加独立分析。

05 / 正式重写留到验证之后

  1. 范围确定：用户实际常用的 6–8 项、个人自用或公开发布目标。
  2. 四份短文档：PRD、DESIGN、TECH、TESTPLAN；包含 macOS 27 状态、权限、键盘/VoiceOver 和恢复规范。
  3. 最小产品：原生菜单栏面板 + 已验证能力，不先建插件、云同步、账号或支付系统。
  4. 日用与分发：状态读回、睡眠唤醒、设备变化、权限撤销、签名公证和回退；完成后才讨论场景组合与最终品牌。
