01 / 结论

推荐 Phase 1
全局快捷键

先做保活开关 + 启动屏保；Carbon 注册本机 status 0，不需要 Accessibility/Automation。

推荐 Phase 2
关闭显示器

公开 pmset displaysleepnow，无 TCC、实现小；作为独立快速动作，不并入锁屏。

暂缓
输出音量

CoreAudio 可行但设备能力不一：本机默认输出（外接显示器音频）不支持 mute/volume。

不纳入
Night Shift

仍依赖私有 CoreBrightness；不接受私有接口维护成本前不实现。

首选理由：快捷键复用已验证能力、无新增权限面、可随时停用；先把“已有能力更快触达”做好，再考虑新增系统状态（音量/设备）带来的设备差异与 UI 维护。

04 / 只读 API 证据

Carbon 全局快捷键

RegisterEventHotKey(
  kVK_ANSI_K,
  cmdKey|optionKey|controlKey,
  ...
) → status 0
UnregisterEventHotKey → status 0

探测进程注册后立即注销；不需要 Accessibility。实现时仍需逐个组合做冲突检测（eventHotKeyExistsErr）。

CoreAudio 设备能力

  • 默认输出（外接显示器音频）：不支持 mute/volume。
  • 内置扬声器 / USB 音频设备 / 部分麦克风：支持 mute/volume。
  • 输入侧也存在设备差异（部分耳机麦克风不支持）。

任何音量/静音实现都必须 capability detection + readback + unsupported 降级。

关闭显示器：man pmset 明确列出 displaysleepnow；本轮未执行。需要真实休眠/唤醒现场验证，不能只凭静态命令算通过。

05 / 推荐路线

Phase 1 · 快捷键（推荐）

  • 设置 › 快捷键：启用开关 + 两个固定组合。
  • 初始：⌃⌥⌘K 切换保活；⌃⌥⌘S 启动屏保。
  • 注册失败/组合被占用时显示可读错误；停用后注销。
  • 只调用现有动作，不新增权限路径；后台失败要有状态反馈。

Phase 2 · 关闭显示器

  • 快速动作独立磁贴「关闭显示器」。
  • 文案明确“显示器休眠，移动鼠标/按键唤醒”，与“锁定屏幕”区分。
  • 实现用公开 pmset；失败显示真实错误。
  • 现场验证休眠与唤醒后再记通过。

Phase 3 · 输出音量（条件）

先解决设备能力与 unsupported 降级；默认输出不支持时不允许显示假成功。麦克风静音、输出设备切换、Night Shift 继续延后/不纳入。

验收要点

  • 快捷键：注册/注销无残留、冲突检测、停用生效、无新增 TCC、设置页键盘/VoiceOver 可达。
  • 关闭显示器：真实休眠/唤醒、失败错误、不误触发锁屏。
  • 音量（后续）：支持/不支持两类设备状态正确，设备切换后刷新。
  • 未执行项不写通过；TCC 相关仍需用户在场。
