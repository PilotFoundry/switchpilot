03 / REA 是分析助手，不是源码恢复按钮

本报告按官方 6.5.0 发布版（2026-10-14）及其固定 commit 文档判断，避免把 main 的后续功能算入已发布版本。[R1]

可提供的帮助

  • 盘点 .app / ZIP / DMG 的文件、hash、结构和入口。[R2]
  • 通过 Hopper / Ghidra / IDA 获得汇编、伪代码、符号、字符串及交叉引用。[R3]
  • 读取部分 ObjC / Swift dispatch metadata，选择 universal 的架构 slice 研究。[R3]
  • 围绕具体开关形成调用、权限、副作用与失败路径的证据台账。

不能保证的事

  • 恢复原始命名、注释、项目结构或可编译的 Swift 源工程。
  • 完整识别 Swift 泛型、resilient、async/coroutine 等复杂路径。[R3]
  • 让旧私有 API 自动兼容 27，或绕过 TCC / 系统安全限制。
  • 替代真实硬件、睡眠唤醒与权限撤销测试。

准备条件：基础文件检查已能直接做。深度原生分析需要 REA 与分析引擎；本次在 PATH / Applications 范围未发现 REA、Hopper 或 Ghidra，未做全盘安装审计。Hopper 是商业工具；Ghidra 需符合运行环境。REA 的 agent MCP/skill 配置与分析器安装是不同步骤。[R4]

REA 本地分析的输出仍可能进入云端模型上下文，“本地分析”不自动等于完全离线。REA 的 MIT 许可证不授予 One Switch 代码、图标或品牌使用权；本报告不对 One Switch EULA 作法律结论。建议独立实现并记录来源，公开分发前核对授权边界。[R5]

不优先

修改原二进制

收益：可能快速验证单个假设。代价：补丁脆弱，无法形成清楚的维护边界。

独立常用功能版

06 / 流程：先把未知变成验收条件

不需要一套厚重文档，但必须让 AI 与人对“做什么、为什么算完成”理解一致。以下是下一阶段建议，尚未执行，也不是已确认的功能优先级。

时间条为示意，可重叠；日用回归与硬件测试有真实的经过时间，不能靠生成代码全部压缩。

阶段 0–1：基线、能力验证与停止条件
  1. 固定研究副本的版本、hash、签名；原应用及用户数据保持原样。
  2. 列出实际使用的开关、具体失效现象与期望；视觉不合规范和功能失效分别记录。
  3. 建 API / 权限 / 硬件 / 副作用 / 恢复台账。REA 只追必要调用链，不全量转储喂模型。
  4. 验证三个代表性能力。权限撤销、睡眠唤醒或失败恢复不能通过的，不列入首版承诺；缺乏可靠接口就提供设置入口或不支持。

07 / macOS 27：平台规范不止玻璃效果

Apple 已确认 27.0.1（26A434）。Liquid Glass 源自 macOS 26 / WWDC25 周期，27 继续演进；并非 27 才引入。WWDC26 AppKit 资料包含 27 的外观、圆角同心布局与状态项键盘交互。27.0.1 发布页未提供其专属设计/API 清单；本报告以 27 官方 release notes 为接口变化依据，并要求在 27.0.1 实机验证，不能把每条说明都视作 27.0.1 新增。[A1–A3]

会影响重写的具体变化：按 Apple 27 SDK release notes，链接 27 SDK 后 NSMenu 菜单项图片默认隐藏；确有语义需要时审查 NSMenuItem.preferredImageVisibility，SwiftUI 菜单审查 .labelStyle(.titleAndIcon)。这是“链接新 SDK”的变化，不只是“运行在 27”。旧应用用 26.4 SDK 构建，重写版需要独立验证。[A2]
维度项目要求验收
原生视觉标准 SwiftUI / AppKit 控件优先，系统材质用于适当层级；自定义容器再处理圆角与间距深浅色、不同壁纸、降低透明度、增强对比度、减少动态效果均可读；不只靠颜色表达状态。[A3]
菜单栏 / 键盘MenuBarExtra 为基线；确有需要才用 NSStatusItem，避免两套并行实现键盘打开/遍历/执行/关闭、VoiceOver、多显示器、全屏和自动隐藏；自定义窗口正确处理焦点生命周期。[A4]
权限Automation / AX / 蓝牙按功能最小化请求。禁止直接访问或改写 TCC 数据库；授权不等于所有系统控制均被允许。新账户首次授权、拒绝、撤销、身份变化后状态；音频属性调整不无故索要录音权限。[A2、A5]
后台 / 特权登录项优先 SMAppService；确需特权才建 helper，限定操作并验证调用者身份系统关闭登录启动后尊重选择；安装/升级/移除可验证；不暴露任意 root 命令入口。[A6]
系统集成受支持 API 优先，私有机制、偏好写入与脚本单列兼容风险每个开关读回真实状态，外部改变后同步；未知不能显示成关闭；不支持要明确降级。
分发先考虑 Developer ID 直接分发；若目标是 App Store，提前审查沙盒与审核约束，范围可能缩小Hardened Runtime、签名、公证、staple、冷启动实测；公证不等于功能兼容或商店批准。[A7]
工具链 / 兼容范围先 macOS 27 / Apple Silicon；旧系统与 Intel 支持是单独选择。用支持目标系统的稳定 SDK。本机 Xcode 27 已有但首次配置未完成；官方 10 月 15 日已列 27.1。本次未升级。[A1]

以上混合了官方平台要求与本报告的工程建议；不是一张“照做就必过审核”的认证清单。原包含私有框架与 SMJobBless，只说明需要审查，不能推导所有功能都必须沿用旧机制。

08 / 新功能要克制，新名字可以现在开始

兼容 27、状态可信、权限和恢复清楚，已足以构成首版价值。你尚未列出必需新功能，以下是候选，不是替你确认的需求。

首版质量目标

真实状态与失败解释

呈现进行中、权限不足、不支持、失败；让“用户点击”与“系统已改变”有清楚区别。

维护价值高；本次未证明原版完全缺少这些能力，不把它包装成确定的新功能。
第二阶段候选
