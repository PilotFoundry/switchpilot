03 / 三项能力：事实、候选、未知

可进入产品候选 常规保活

原行为：主程序 0x1000366c8 启动 /usr/bin/caffeinate，常量含 -d、-w 并追加 PID。0x10003566c 清理旧 timer/process 后按开关重建；timer 闭包经 0x100039778 → 0x1000365ac terminate 进程并更新状态。

独立实现：使用公开 IOKit 的 PreventUserIdleDisplaySleep assertion，按 ID 读回真实类型/级别，关闭时释放；无需原版特权 helper。

此功能保持显示器不因空闲休眠；不承诺阻止合盖、手动睡眠或低电量睡眠。原版“合盖也不睡眠”是另一条特权路径，本轮排除。

查看可定位证据及推断边界

待授权验证 系统深色模式

原行为：包内编译脚本包含 System Events 及术语码 aprp/thme，与本机脚本字典的 appearance preferences / dark mode 相符。通用脚本执行器入口 0x100007bf8 加载资源后执行 NSAppleScript；0x10004fe60 根据 AppleInterfaceStyle/Dark 查询状态。

候选：自写 AppleScript + 新 bundle identity + 用途说明/Automation entitlement + 写后读回。NSApplication.appearance 只改变本应用，不能替代系统外观切换。

未验证：源脚本未恢复；新原型无授权，未执行 setter。真实允许/拒绝/撤销、切换后恢复、与系统自动排程的竞争仍需测试。

首版暂不直接控制 Night Shift

原行为：XPC 直接链接 PrivateFrameworks/CoreBrightness。0x1000012c4 懒加载 CBBlueLightClient；0x100001350 读取 getBlueLightStatus:，0x1000014e0 调用 setEnabled:。

接口边界：在 Apple 官方文档与本机 macOS 27.0 公共 SDK headers/Swift interfaces 的限定检索中，未找到公开控制 API。更好看的伪代码不会改变这个限制。

本轮没有执行私有 setter、验证显示器支持性或恢复策略。可另评估系统设置入口，不能提前承诺直接开关等价。

04 / 动态验收：通过与缺口分开

检查结果实测解释
同进程开关 ×3通过IOPM 读回 type / level；重复 start 同一 ID；stop 后 ID 消失
对象释放通过deinit 后 OS 不再持有该断言
定时进程 ×3通过每次 2 秒；pmset 按 PID 关联断言，退出 0 后无残留
SIGTERM / SIGKILL通过只操作本脚本子进程；退出 −15 / −9，系统回收断言
深色权限需授权首次 −600；启动 System Events 后 −1744。无弹窗，不是实际拒绝
深色切换 / 恢复未验证代码候选已构建；实际 setter 执行 0 次
睡眠、合盖、重启、设备变化未验证本轮没有打断用户会话做这些测试

原型由 CLT Swift 6.4 构建，并使用独立 ad-hoc Hardened Runtime 签名。完整 Xcode 的许可未接受，CLT 缺少 XCTest；改用可执行自检，先得到 0/4 失败再实现到 4/4 通过。

构建不是零警告：SwiftPM 的 native build system 已提示弃用。该回退只用于本轮；正式产品需要完整 Xcode 环境。原型没有 UI、分发签名、公证或 Sandbox 验收。

术语表

slice：通用 Mach-O 中的一种 CPU 架构副本；hash 与原通用文件不同。

伪代码：分析器对机器码的近似解释，类型/参数可能错误，不能当原始源码。

power assertion：进程向系统声明暂时的休眠限制；释放或进程退出后由系统处理。

Automation / TCC：跨应用控制权限及 macOS 隐私授权机制；有 entitlement 不等于已经获准。

ad-hoc 签名：本机原型身份标识，不等于 Developer ID 分发签名或公证。
