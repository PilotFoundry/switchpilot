# 设置页「权限」撤销授权：disclosure 方案评审

- 评审人：ux-reviewer｜2026-10-18 12:35｜对象：v0.3.3 成功态截图（`/tmp/settings-permissions-current.webp`）+ `SettingsView.swift:35-101`；只读评审：未触发 TCC/系统设置、未运行应用或登录项；与 `docs/PRD.md`/`docs/TECH.md`/`README.md` 的"应用内不执行 tccutil reset"一致。

## 结论（可直接执行）

1. **撤销说明不常驻**：下沉为权限卡底部一个默认折叠的 disclosure；成功态首屏只保留两行状态 + [重新检查] +「管理权限…」。
2. **一级标签用「管理权限…」**（DisclosureGroup）。不建议"撤销授权…"：应用不能执行撤销，标签会承诺不存在的动作；"如何撤销授权…"只做展开后的组内小标题（若团队坚持动词导向，退而求其次选它，绝不选"撤销授权…"）。
3. 展开后**必须分开两条路径**，视觉与文案分级：
   - **推荐：在系统设置中撤销（安全、可随时恢复）**——说明 + [打开自动化设置] [打开辅助功能设置]。
   - **高级（谨慎）：终端重置记录**——只展示 bundle-scoped 命令 + [复制命令]，**应用绝不执行**；写明风险、恢复方式、"不要 sudo、勿用 `reset All`"。
4. **成功态删除蓝色主按钮「申请全部权限」**：此时是 no-op，且暗示"还缺权限"；改为 §2 的三态 CTA。
5. 现在常驻的两个"打开…设置"按钮与长段 API 免责声明移入展开内容：成功态它们既占空间，又容易被误读为"继续授权"。

## 1. 理由与风险

- HIG Settings（只放低频设置、减少堆叠）/ Privacy（撤销引导到系统隐私面板、应用不代替用户做不可逆操作）：敏感低频操作适合渐进披露。
- 可恢复性分级：系统设置取消勾选**可逆**；`tccutil reset` 清除记录**不可逆**、提示可能不再出现、Accessibility 需重新手动勾选——不能同段并列。
- 误触/发现性：成功态 [申请全部权限] 与两个"打开…设置"按钮相邻却指向相反意图，tccutil 常驻会让高风险命令显得像普通说明；折叠后默认不可见即可消除，折叠标签 + tooltip/accessibilityHint 足以承担发现性，无需常驻长文。
- 不新增"撤销授权"红色按钮：应用没有可执行的破坏性动作，做成 destructive 按钮反而违反 macOS 惯例、提高误触预期。

## 2. 三态（含拒绝）行为

| 状态 | 行呈现 | 主 CTA | 次级 | 撤销 disclosure |
|---|---|---|---|---|
| 全部授权 | ✓/✓ 已授权 | **无**（删除"申请全部权限"） | [重新检查] | 折叠「管理权限…」 |
| 部分授权（恰缺 1 项） | 缺失行橙色 + 原因 | 仅缺失项：[去授权辅助功能] 或 [申请 Automation 授权]；Automation 已拒绝→[打开自动化设置] | [重新检查] | 折叠；展开仍给两个设置入口 |
| 未授权/未决定（两项都缺） | 两行橙色 | [申请全部权限] primary | [重新检查] | 折叠 |
| 已拒绝 | 对应行红色"已被拒绝" | [打开系统设置] | [重新检查] | 折叠 |
| 检查中（busy） | 保持上次状态 | 全部按钮禁用 + 文案"检查中…" | — | 可展开但按钮禁用 |

原则："申请全部权限"只在两项都未授权/未决定时出现；部分授权只显示缺失项 CTA，避免重复申请已授权的项。

## 3. 推荐布局 / 文案（ASCII）

```
[权限卡 · 成功态]
只在需要时申请；不授权也可使用保持亮屏与启动屏保。
✓ Automation（System Events）          已授权
✓ 辅助功能（Accessibility）            已授权
                              [重新检查]

▸ 管理权限…
```

```
▾ 管理权限…
  在系统设置中撤销（推荐，可随时重新开启）
  系统设置 › 隐私与安全性 › 自动化 / 辅助功能，取消勾选 SwitchPilot。
  [打开自动化设置]  [打开辅助功能设置]
  ───────────────────────────────────────────────
  高级（谨慎）：重置本应用授权记录
  ⚠ 仅在“系统设置已开启但仍显示未授权”时使用；应用不会执行，只提供复制。
  tccutil reset AppleEvents local.personal.SwitchPilot
  tccutil reset Accessibility local.personal.SwitchPilot
  [复制两条命令]
  后果：清除本应用授权记录；可能需退出并重开应用；系统提示可能不再出现；辅助功能需重新手动勾选。仅限当前用户；不要 sudo，勿用 reset All。
```

- 复制按钮文案："复制两条命令"；点击后就地反馈"已复制"（不用弹窗）；命令文本可选中，便于核对 bundle id。
- 撤销后从系统设置返回：设置窗回前台并自动刷新（v0.3.2 已有外部设置监测），行状态与缺失项 CTA 自动切换；[重新检查] 保留兜底。

## 4. 可达性 / 键盘 / VoiceOver

- 用 SwiftUI `DisclosureGroup`：标签本身可 Tab 聚焦、Space/Return 展开，自动暴露展开/折叠状态；`accessibilityLabel("管理权限")`、`accessibilityHint("展开查看在系统设置中撤销授权及高级重置命令")`。
- 展开后焦点顺序：`[重新检查]` → disclosure → `[打开自动化设置]` → `[打开辅助功能设置]` → `[复制两条命令]`；全部为真实 Button，不用仅手势。
- 状态不只靠颜色：行已有"已授权/未授权/已被拒绝"文字；"高级（谨慎）"同时用图标+文字，不单靠橙色。
- 复制按钮 `accessibilityLabel("复制两条重置授权命令")`；命令文本对 VoiceOver 可读、可选中；禁用态（busy）不隐藏焦点。展开内容较长时让设置窗自适应高度/滚动，避免小屏截断。

## 5. 不推荐做法

- 常驻"如何撤销授权"大段说明 + 两个按钮（现状）：信息噪声、误读为授权入口、把不可逆命令日常化。
- 一级标签"撤销授权…"或红色 destructive 按钮：应用不能撤销，承诺落差。
- 应用内运行 `tccutil reset`：违背 docs/README 声明；破坏可恢复性；即使加二次确认也不建议。
- `tccutil reset All`、`sudo`、无 bundle id：禁止出现在任何文案/命令中；不要把 tccutil 与"打开系统设置"混在同一无分级文本里。

## 6. 验收点

1. 全部授权默认视图：无"申请全部权限"主按钮；只有两行 ✓ + [重新检查] + 折叠「管理权限…」；卡片高度明显下降。
2. 展开后：推荐路径与高级区清晰分隔；两个设置按钮可用；tccutil 仅展示+复制，应用不执行（源码/日志核对）。
3. 部分授权：只出现缺失项 CTA；全部授权项无按钮；"申请全部权限"不出现。
4. 拒绝态：主 CTA 为[打开系统设置]，无"申请"类按钮；文案说明需在系统设置重新开启。
5. 撤销后返回：设置窗回前台自动刷新，行状态与 CTA 正确；无"已授权"假状态。
6. 键盘/VoiceOver：Tab 可达 disclosure，Space/Return 展开；VO 读出标签、状态与 hint；复制按钮有明确名称；浅/深色下对比度可读（与 ui-reviewer 复核）。
7. 误触：折叠态看不到 tccutil；展开后复制命令不触发任何系统变更；点击"打开设置"只打开面板、不改变授权。

## 7. 依据与限制

- HIG [Settings](https://developer.apple.com/design/human-interface-guidelines/settings)（低频设置、减少选项）、[Privacy](https://developer.apple.com/design/human-interface-guidelines/privacy)（用户控制、系统隐私面板）、[Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)（不只靠颜色/可聚焦）；Apple [tccutil reset 文档](https://developer.apple.com/documentation/xcode/resetting-access-to-protected-resources-in-macOS)（默认仅当前用户；sudo 才所有账户；`reset All` 清空所有应用决定）。
- 本评审为静态评审：未运行应用、未实际展开/撤销；动画、长文案换行与 VoiceOver 实际读数需手测确认（尺寸 460pt、浅/深色各一次）。
