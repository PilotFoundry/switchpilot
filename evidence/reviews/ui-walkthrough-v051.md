- 评审者：独立 UI 评审（只读）。未改源码/文档/Git，未触发 TCC、屏幕、麦克风、登录项状态。
- 基线：v0.5.1（HEAD dac2aac）；截图 `/tmp/walkthrough-v051/*.png`（2x 离屏渲染）；源码 `PanelView`/`SettingsView`/`Theme`/`ScreenCleaningManager`；`docs/CORE.md`、DESIGN §10.4-13。
- 方法：截图 alpha 实测尺寸 + 逐屏目视；代码核对状态/退出/无障碍；对比度沿用已验收的 token 计算（secondaryInk 5.07–6.22 light / 5.79–7.47 dark，errorInk 8.05 dark）。未重跑 dump。
- 参考：One Switch 原版仅作布局参考（列表行、右侧开关、行内说明），不引入其已排除功能。

## 结论

- **无 P0**。核心定位与视觉语言（不透明表面、secondaryInk、系统控件、SF Symbols、统一圆角）保持稳定；v0.3.8 的屏保副标题问题已修（现为「启动 · 鼠标退出」），权限重复 callout 已收敛为单张「需要授权」卡（guide 可见时隐藏）。
- **P1 两项**：① 面板密度/高度（实测约 813pt，guide 约 861pt；900pt 屏上占 90–96%，小屏会接近满屏）；② 麦克风静音的状态只在面板内可见，关闭面板后菜单栏仍是静态 S，未满足 CORE §3.6「状态必须可见、持续可理解」。
- **P2 若干**：快速动作 4 行常驻「未执行」与磁贴副标题重复、3 列磁贴偏挤、设置页快捷键/登录卡说明冗长、清洁遮罩自绘按钮缺 VoiceOver 语义。均可在不改功能范围的情况下修。
- 不建议把 One Switch 的整套列表照搬：保持亮屏有分段+进度，仍是主操作；只把**次要状态行/动作**改为更紧凑的列表/网格模型（见下）。

## 借鉴 One Switch 的布局（只借层级/密度，不借功能）

One Switch 有效点：单列行、左侧功能名、右侧开关、状态只占一行（如「永久」），不支持项用行内红字而不是新卡；footer 一行操作。当前面板的问题是每个能力都升级成一张大卡 + 常驻状态行。

推荐结构（ASCII，目标 380×≤650 折叠 / ≤720 展开）：

```
[S] SwitchPilot           ● 保活关闭
┌ 保持亮屏                             [switch] ┐
│ [15][30][60][无限期]                          │
│ 剩余/未开启 · 不阻止合盖/手动睡眠              │
└──────────────────────────────────────────────┘
深色模式      系统当前：浅色                  [switch]
麦克风        MacBook Pro 麦克风      [静音麦克风]
──────────────────────────────────────────────
快速动作   [屏保] [锁屏] [显示器] [清洁]
           （仅非默认/错误时显示一行结果）
──────────────────────────────────────────────
需要授权（仅在缺权限时）：说明 + [申请全部权限][重新检查]
footer：使用说明 · 设置… · 退出
```

要点：只保留「保持亮屏」为卡（主操作）；深色模式/麦克风改为单行（状态在行内）；快速动作 2×2 或 4 列紧凑按钮，状态行改为**条件显示**（例如 `上次操作/错误`，成功静默）；清洁屏幕保留全宽按钮或并入动作网格；权限卡只在未就绪时出现。预计可省 120–160pt 高度。

## 开项（P0/P1/P2）

**P1-1 面板高度与信息密度（可落地）**
- 证据：`panel-light`/`panel-dark` 离屏内容约 813pt（DESIGN §10.5 记 788，guide 861）；`verify-app.py` L190-198 阈值 840/900 过宽；小屏 visibleFrame 下会接近满屏。
- 原因：5 张卡 + 4 行常驻状态 + 3 列磁贴 + 独立清洁行；重复表达同一状态（如「屏保：未执行」+ tile 副标题「启动 · 鼠标退出」）。
- 修复：按上面结构压缩；状态行仅显示非默认值/错误/最近一次结果（例如「屏保：已请求启动（未确认）」），成功且无需关注时不显示；把「清洁屏幕」并入动作区。验收：`--dump-panel` 无 guide ≤660、有 guide ≤740，且屏幕 1280×800 下底部按钮可见。

**P1-2 麦克风静音状态不可持续感知（CORE §3.6）**
- 证据：PanelView L246-305 静音态用 errorInk 文案「麦克风已静音」+ `取消静音` 按钮，只在 popover 打开时可见；菜单栏 StatusIcon 始终静态 S（无状态变体），面板关闭后无提示。
- 风险：用户静音后忘记恢复，影响录音/会议；这属于 CORE 明示的"隐私/输入类必须持续可见"。
- 修复（不改架构）：`StatusIcon.make(muted:)` 增加一个 template 变体（S + 斜线/圆点，仍单色），`AppDelegate` 在 mic 状态变化时刷新 statusItem 并更新 `button.toolTip`/accessibilityDescription；面板重开时状态不变。验收：静音→关闭面板→菜单栏图标仍可辨（用户现场，加 M12 扩展）；取消静音后恢复。若不接受图标变体，至少给 tooltip + 菜单栏右键菜单状态（需新增菜单，优先级降为 P2 但需记录理由）。

**P2-1 快速动作 3 列磁贴偏挤**：380pt 内每列约 108pt，「关闭显示器」+两行副标题已接近换行极限；建议 2×2 网格（每列 ~160pt）或 4 列纯图标+短标签，统一 tile 高度；清洁屏幕可与动作同组。验收：三语种/大字号下不换行断词。

**P2-2 设置页文案密度**：快捷键卡 4 行说明（组合、行为、冲突、TCC）对"默认关闭的实验项"偏重，建议首屏只留「启用全局快捷键」+ 一行组合说明，其余入 disclosure/帮助；登录卡三段说明可合并为一段；「关于」卡与窗口底部「个人自用」重复。验收：设置窗口折叠态 ≤560pt（当前 625pt），一屏可扫完。

**P2-3 清洁遮罩的按钮与无障碍**：黑色全屏 + 白字 + 白色「退出清洁模式」按钮层级清楚、指令「移动鼠标并点击下方按钮」明确；多显示器已在代码中遍历（ScreenCleaningManager L139）。遗留：`CleaningExitControl` 为自绘 NSView，未见 accessibilityLabel/Role（键盘被锁，VoiceOver 用户需可聚焦的退出按钮）；建议设置 `setAccessibilityRole(.button)`、label「退出清洁模式」、以及进入/退出时 `NSAccessibility` 通知；M13-4 无权限降级仍待补（不进入"看着像清洁但没锁输入"的状态）。

**P2-4 权限卡位置/文案**：单张卡已比之前好，但位于动作区之后，图标+三行说明+按钮仍偏重；建议压为两行（缺什么 +「申请全部权限」/「重新检查」），并在深色模式/锁屏行内保留必要提示。CORE 要求诚实降级，保留文案但可收紧。

## 关项（对照旧报告，不再算问题）

- 屏保副标题已与点击即执行一致（「启动 · 鼠标退出」）；锁屏「锁定 · 密码解锁」、显示器「休眠 · 鼠标唤醒」同样明确了退出/恢复路径。
- 权限重复 callout 已收敛为单卡；guide 可见时隐藏的机制保留；磁贴仍为系统 bordered，hover/pressed/focus 可用。
- 图标/monogram、设置成功态（无蓝色申请按钮）、撤销 disclosure、自动窗口高度等 v0.3.x 已通过项未回归（本次不重开）。
- 清洁遮罩结构（全屏覆盖所有屏、无倒计时、鼠标退出、启动断言）符合 CORE §3.7；仅剩无障碍与降级验收。

## 验收点（复评通过口径）

1. `--dump-panel`：无 guide ≤660、有 guide ≤740；1280×800/大字号下 footer 与权限按钮可见；`verify-app` 阈值同步收紧。
2. 常规成功态不出现 4 行「未执行」；仅在操作后/错误/未确认时出现一行结果，且与磁贴一致。
3. 麦克风静音→关闭面板→菜单栏有持续可辨状态；取消静音恢复；tooltip/accessibilityDescription 正确（用户现场，M12 扩展）。
4. 设置页折叠态可一屏扫完；快捷键卡默认关闭、组合说明不淹没主状态；登录卡与关于卡无重复句。
5. 清洁模式：所有显示器均覆盖；退出按钮 VoiceOver 可聚焦/读出；M13-4 无权限时显示授权引导，不进入伪清洁态。
6. 深色/浅色/大字号下对比度与布局保持（secondaryInk ≥4.5，按钮层级不变）。
